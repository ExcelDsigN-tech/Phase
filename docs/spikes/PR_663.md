# feat(api): version negotiation, deprecation headers and a breaking-change gate (spike 663)

## Summary

Versions the public HTTP surface. Middleware negotiates `X-API-Version` / `Accept-Version` on `/api/*`, echoes the version, and answers unknown versions with a typed `406` and retired ones with `410`. Deprecated routes get RFC 9745 `Deprecation` and RFC 8594 `Sunset` headers. A machine-readable OpenAPI contract and changelog are generated from one source, and a blocking CI step stops unversioned breaking changes. Runtime behavior is behind `phase-api-versioning` (default off).

## Changes

- `lib/api-contract.ts`: typed contract for 24 operations; statuses read per handler.
- `lib/api-versioning.ts`: negotiation, `versionResponseHeaders`, `API_VARY_TOKENS`, OpenAPI 3.1 builder, `diffContracts` and `checkContract`.
- `middleware.ts`: negotiation for `/api/*` (preflights excluded). The flag off returns the same response as before.
- `lib/api-observability.ts`: logs and echoes the negotiated version (known ids only).
- `GET /api/versions`: summary, or the OpenAPI document with `?format=openapi`.
- `docs/api/openapi.json`, `docs/api/changelog.json` via `npm run api:contract -- --write`.
- `.github/workflows/ci.yml`: blocking contract gate against the target branch snapshot.
- `scripts/proof-api-versioning-663.ts` (`npm run proof:663`): read-only live proof.

## Behavior notes

- `Vary` is a superset of every token an `/api` route sets, including `Authorization`, so gated responses keep their cache key. A test scans `app/api` to keep the list complete.
- The requested version value is never logged. Rejections log only `error` and `status`.

## Flag and rollback

`FEATURE_PHASE_API_VERSIONING` / `NEXT_PUBLIC_FEATURE_PHASE_API_VERSIONING`, default off. Rollback: unset and restart. No negotiation or version headers, `/api/versions` returns 404, nothing persisted. The CI gate is source-only and stays on.

## Tests

- `lib/__tests__/api-versioning.test.ts` (19): negotiation precedence, 406/410, RFC header formats, path-template deprecations, the Vary superset scan, contract coverage, snapshot freshness, diff and gate rules, and middleware flag off/on.
- `tsc --noEmit`: 0 errors. `vitest run`: green with flags off. Locally, `npm run proof:663` passed all 15 checks against `next dev` with the flag on.

## Live proof

Production build run: 15/15 checks pass with the flag on. With the flag off, `/api/versions` is 404 and no version headers appear. `/api/metadata/[id]` keeps `Authorization` in `Vary`. Details are in the spike doc under "Lab results". No preview deploy; proofs were run against a local production build and `next dev`.
