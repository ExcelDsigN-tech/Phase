# feat(cli): phase-creator command tree with offline metadata validation (spike 661)


The flag is `phase-165` because upstream #573 assigned `phase-161` to the typed contract-error taxonomy. Set `FEATURE_PHASE_165=1` to enable it.

## Summary

Adds `phase-creator`, one CLI for creators who never open the web app. It scaffolds a collection, validates it offline against the exact on-chain rules, pins assets headlessly, checks the env, and deploys to testnet. Output is CI-friendly: `--json`, `--dry-run`, `--network`, and exit codes 0–5. Everything is behind `phase-165` (default off).

## Changes

- `lib/creator-cli.ts`, `scripts/phase-creator.cts`, `bin: phase-creator`, `npm run creator --`: `scaffold`, `validate`, `env`, `pin`, `deploy`, `run`.
- `lib/creator-metadata-rules.ts`: a byte-exact port of `str_is_safe_for_json_fragment` plus the price rule, with shared parity vectors in `contracts/phase-protocol/test-vectors/` read by vitest and `src/test.rs`.
- `lib/ipfs-upload-retry.ts`: `resolvePinataJwt` (now also used by `POST /api/ipfs`) and `scrubSecret`.
- `lib/env-validation.ts`: `diagnoseCreatorEnv`, reused by `diagnose-env.ts`.
- `scripts/creator-preflight.ts`: thin-wrapper preflight called before `main()` in the ten listed scripts. `--dry-run` prints the plan and exits 0. The flag-on env check exits 3. Flag off, it's a no-op.
- `scripts/proof-creator-661.ts` (`npm run proof:661`): live proof runner.

## Behavior notes

- The contract accepts non-ASCII, so the validator warns on it instead of rejecting it (the issue asked for rejection; see the spike doc).
- Found: `validateCollectionImageUri` counts UTF-16 units while the contract counts UTF-8 bytes. Documented with a test, not changed here.

## Flag and rollback

`FEATURE_PHASE_165` / `NEXT_PUBLIC_FEATURE_PHASE_165`, default off. Rollback: unset it. Side-effecting commands exit 5, wrapped scripts behave exactly as before, and nothing is persisted.
